# Наблюдаемость в эксплуатации
## 1. Логирование 

Отдельной телеметрии для ML нет. Есть audit log, куда пишется каждое решение (инвариант 3 в [architecture.md](architecture.md)). ML-мониторинг — это агрегаты по этой таблице. 

Полные промпты и ответы хранятся не для всех: 1% случайной выборки плюс **все** блокировки output guard, все деградации и все жалобы. Хранить всё дорого, а поэтому храним только то, что нужно разбирать.


## 2. Технические метрики

| Метрика | Цель | Зачем |
|---|---|---|
| Латентность горячего пути p99 и разбивка по шагам | ≤ 500 мс | контрактный бюджет ([architecture.md](architecture.md), раздел 6); без разбивки непонятно, что именно поехало |
| Ошибки 5xx на приёме | ≈ 0 | приём обращений не имеет права падать |
| **Время ожидания в очереди p95** | ≤ 5 мин | индикатор отставания медленного пути |
| Время до отправленного ответа | по SLA из [product.md](product.md) | латентность API ничего не говорит пользователю: он ждёт ответ, а не `202` |
| Состояние circuit breaker, доля таймаутов LLM | breaker закрыт > 99% времени | открытый breaker = вся генерация ушла людям |


## 3. ML-метрики

Истина приходит с задержкой: правильность автоответа выясняется через дни, а решение принято сейчас. Путать эти две группы нельзя.

| Метрика  | На что реагирует |
|---|---|
| Доли решений `auto` / `suggest` / `review` / `reject`  | самый чувствительный индикатор: сдвиг долей при неизменной `model_version` означает, что изменился вход 
| Доля обращений с пустым или слабым контекстом retrieval  | база знаний не покрывает то, о чём спрашивают |
| Доля «прочее» и доля новых кластеров  | заявка на новую категорию, а не шум |
| Доля блокировок output guard  | рост вдвое = генерация начала выдумывать либо испортился контекст |
| **Precision автозакрытия**  | считается только на придержанной контрольной группе 1% ([ml.md](ml.md), раздел 8); на всём потоке истины по автозакрытым нет по построению |
| Reopen rate автоответов  |  |
| Калибровка ECE на скользящем окне  | если ECE уехал, порог перестал означать то, что означал: это отдельная поломка, не связанная с точностью. Порог — в [ml.md](ml.md), раздел 3 |

Продуктовые метрики — North Star и четыре guardrail — определены в [product.md](product.md); здесь важно только, как они снимаются: доля автозакрытия и SLA считаются из журнала, reopen по когортам, CSAT отдельно по авто и ручным ответам (общий разбавлен и скрывает проблему), а guardrail по небезопасным автоответам меряется ручным разбором недельной выборки.

## 4. алерты

| Алерт | Условие | 
|---|---|
| Горячий путь вне бюджета | p99 > 500 мс 5 минут подряд | 
| Очередь растёт | ожидание p95 > 5 минут | 
| Генерация недоступна | breaker открыт > 10 минут | 
| **Сдвиг в решениях** | доля `auto` изменилась > 5 п.п. за час при неизменной `model_version` | 
| Небезопасный автоответ | ≥ 1 на недельной выборке | 
| Стоимость на обращение | рост > 30% неделя к неделе |
