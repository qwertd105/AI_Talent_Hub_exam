# Автоматизация обработки тикетов поддержки

AI/ML-система для поддержки крупного онлайн-сервиса: 200k обращений в день, четыре канала, пики до 20k за 10 минут во время инцидентов. Система принимает обращение, за десятки миллисекунд решает **что это и куда направить**, и отдельно, асинхронно, готовит **текст ответа**. Рискованные категории не закрываются автоматически ни при какой уверенности модели.

## Зачем это бизнесу

Оператор до 40% времени тратит на обращения, ответ на которые уже написан в базе знаний. Автозакрытие 15% потока даёт около **1,46 млрд ₽ чистого эффекта в год** при стоимости LLM-инференса порядка 2% от этой экономии — то есть ограничение проекта не деньги, а качество и безопасность. Пользователь получает ответ на типовой вопрос за секунды вместо пятнадцати минут, а сложный case попадает сразу в нужную очередь. Отдельно система создаёт ценность там, где сегодня SLA сломан структурно: в инциденте на 20k обращений физически невозможно выставить 10 700 операторов, и дедупликация — единственный способ ответить всем. Расчёт и допущения — в [docs/product.md](docs/product.md).

## Как запустить

```bash
PY=/path/to/python                 # нужен Python 3.11+
make install PY=$PY                # или: $PY -m pip install -r requirements.txt
make test PY=$PY                   # 37 тестов
make demo PY=$PY                   # оба сценария одной командой
make run PY=$PY                    # сервис на http://localhost:8000
```

Провайдер генерации по умолчанию — `stub`: детерминированный ответ, собранный из найденного контекста, без обращения в сеть. Живая генерация включается `LLM_PROVIDER=ollama`. Внешние ключи не нужны нигде.

## Какие сценарии демонстрируются

| Сценарий | Что показывает | Тест |
|---|---|---|
| **Happy path** | типовой вопрос → категория `howto`, уверенность 0.95, решение `auto` → поиск фрагмента → ответ со ссылкой на статью, человек не участвует | `tests/test_happy_path.py` |
| **Рискованный путь** | «верните деньги, карта 4111…» → номер карты замаскирован, категория `refund`, **уверенность высокая, но решение `review`** → очередь оператора → вердикт человека в журнале как `human:<id>` | `tests/test_escalation.py` |
| Деградация | LLM недоступен → circuit breaker → обращение уходит оператору, а не 5xx пользователю | `tests/test_degradation.py` |
| Нормализация каналов | email (тема + тело) обрабатывается так же, как сообщение в чате | `tests/test_scenarios.py` |
| Режим `suggest` | уверенно, но категория закрыта для автоответа → черновик оператору, пользователю ничего | `tests/test_scenarios.py` |

Проверить руками:

```bash
curl -s localhost:8000/v1/events -H 'content-type: application/json' \
  -d '{"text":"Как выгрузить отчёт? Где найти аналитику?"}'      # decision=auto
curl -s localhost:8000/v1/events -H 'content-type: application/json' \
  -d '{"text":"Хочу возврат денег, карта 4111 1111 1111 1111"}'  # decision=review
curl -s localhost:8000/v1/review        # очередь оператора
curl -s localhost:8000/metrics          # доли решений, вызовы LLM
```

## Что реализовано, а что архитектурный дизайн

Реализовано кодом: приём и нормализация обращений, маскирование PII, детекция prompt injection, классификация, роутер с четырьмя решениями, аудит каждого решения до отправки ответа, очередь медленного пути, генерация через адаптер с таймаутом и circuit breaker, очередь ревью с вердиктом оператора, деградация при недоступности LLM, метрики.

Осталось дизайном: дедупликация и инцидентный режим, output guard, обученный классификатор вместо правил, векторный поиск вместо словаря. Полная таблица с границей сделанного — раздел 12 [docs/architecture.md](docs/architecture.md).

**Главное упрощение:** прототип подтверждает контур принятия решения и безопасности, но почти ничего не говорит о качестве ответа — retrieval и генерация заглушены. Это осознанный выбор: за таймбокс можно было либо довести до зелёных тестов контур эскалации, либо изобразить качество ответа на трёх статьях базы знаний. Подробнее — [SELF_REVIEW.md](SELF_REVIEW.md).

## Допущения и ограничения

- Категория определяется правилами по ключевым словам, уверенность — функция числа совпадений. Это **не** калиброванная вероятность; в целевой архитектуре здесь линейная модель поверх эмбеддингов ([docs/ml.md](docs/ml.md)).
- Порог автозакрытия 0.9 (`AUTO_THRESHOLD`) — иллюстративное значение. Требование ≥ 90% точности выведено из цены ошибки, само значение порога подбирается на реальных данных.
- Хранилище — SQLite, очередь — в процессе. Замена на Postgres/ClickHouse и брокер локальна и не трогает домен.
- Идемпотентность по заголовку `Idempotency-Key` реализована в коде, но в архитектурный документ не вынесена как несущественная для основной идеи деталь.
- Под кейс переписывается только `app/domain/tickets.py`; остальные модули доменно-независимы, это проверяется тестом `tests/test_domain_swap.py`.
